## 1. 背景与目标

P0 阶段已完成「环境地图可切换 + 真值桥接 + 数据采集 + evo 评测前置」。
本阶段（P1）目标是把退化检测做成**可运行的算法模块 + 完整的评测闭环**：

1. **双检测器架构**（用户确认的方案）：
   - **内嵌精确检测器（主）**：直接使用 FAST-LIO 求解中真实参与 IEKF 更新的测量 Jacobian，
     输出精确的 LiDAR geometric Hessian 分数，反映算法内部实际几何约束；
   - **外部几何代理检测器（旁路）**：从 `/cloud_registered` 点云几何结构重新估计退化程度，
     验证"内部状态"与"外部几何趋势"的一致性。
2. **评测闭环**：Gazebo GT 采集 → FAST-LIO 轨迹采集 → 时间/坐标对齐 → ATE/RPE（evo）→
   运行耗时/CPU/内存 → 受控退化场景 → weak direction 与 GT 误差方向对照。
3. **P1 边界**：只做检测 + 评测，**不改动 FAST-LIO state update**（P2/P3 再做自适应）。

## 4. 具体改动说明

### 4.1 消息接口包 `lio_interfaces`

**`DegeneracyScore.msg`**（P1 主消息）字段与理论口径：

```text
std_msgs/Header header
float64 score                # 0~1, 1=严重退化; EMA + 滞后后输出
bool   is_degenerate         # 平滑后的稳定退化标志（P3 自适应控制信号）
float64 trans_ratio          # Ht 平动块 λmin/λmax    【P1 主判据】
float64 rot_ratio            # Hr 转动块 λmin/λmax    【P1 主判据】
float64 condition_number     # 完整 6DoF Hessian 条件数（辅助记录）
float64 normal_concentration # 法向量方向集中度 μ1/Σμ（辅助解释指标）
float64[6] eigenvalues       # 完整 6DoF Hessian 特征值（升序, 保存供 P2/P3）
float64[6] weak_direction    # 最小特征值特征向量（P3 方向性抑制用）
uint32 effective_feature_num # 有效匹配点数量（区分真正退化 vs 匹配失败）
float64 mean_residual        # point-to-plane 平均残差 (m)
float64 pos_x / pos_y / pos_z
```

**理论口径（重要）**：`trans_ratio / rot_ratio / eigenvalues / weak_direction` 均来自 FAST-LIO
求解过程中真实参与 IEKF 更新的测量 Jacobian（`h_x`）累积得到的 **LiDAR geometric Hessian /
measurement Hessian**。它只反映当前 scan-to-map 匹配提供的几何约束，**不是滤波器完整信息状态**
（不含 measurement noise、state covariance），因此不称为"EKF 精确信息矩阵"。

**`DegeneracyIteration.msg`**：`iteration / frame_index / total_residual / mean_residual /
effective_feature_num / trans_ratio / rot_ratio / lambda_max / lambda_min`，
用于 debug 模式分析退化环境下 IEKF 迭代收敛行为（迭代数是否增加、残差收敛是否变慢）。

### 4.2 FAST-LIO 内嵌精确检测器（`laserMapping.cpp`）

新增全局参数（默认值）与 `DegeneracyData` 结构，全部计算包在 `if (degeneracy_enable)` 门控内：

```text
degeneracy_enable        (false)    # 默认关闭 = 与原始 FAST-LIO 数值等价（零侵入）
threshold_t / threshold_r (0.02)    # Ht/Hr 的 λmin/λmax 退化阈值
ema_alpha (0.5)                    # score EMA 平滑系数
score_enter (0.4) / score_exit (0.2)  # 滞后状态机双阈值
min_enter_frames (3) / min_exit_frames (5)  # 连续帧确认
debug_iterations (false)           # 额外发布 /lio/degeneracy_iterations
```

**算法**（在 `h_share_model()` 构造完 `h_x` 后、每帧发布一次）：

```text
前 6 列 = [n(平动, 列0-2), A=p×n(转动, 列3-5)]   ← 真实参与 IEKF 更新的 Jacobian
Ht = Σ n nᵀ                     (3×3 平动块, 世界系)
Hr = Σ A Aᵀ                     (3×3 转动块, body 系)
H6 = Σ h_x[i,0:6]ᵀ h_x[i,0:6]   (6×6 完整 geometric Hessian, 仅保存)
→ trans_ratio / rot_ratio / normal_concentration / condition_number
→ weak_direction = H6 最小特征值特征向量（P3 用）
→ raw_score = max(1−trans_ratio/τ_t, 1−rot_ratio/τ_r) 裁到 [0,1]
→ EMA 平滑 + 滞后状态机（进入/退出不同阈值 + 连续帧确认）
```

**工程要点**：
- 发布器为全局指针，在节点构造函数初始化；`h_share_model` 自由函数可直接访问（沿用 FAST-LIO 全局变量风格）。
- 迭代计数：`degen_data.iter_count` 在 `kf.update_iterated_dyn_share_modified(...)` 前清零，
  `h_share_model` 内自增 → 可在 debug 模式逐迭代发布。
- 发布语义：**每次 LiDAR measurement update 收敛后一次**（自然跟随 scan rate，不写死 10Hz）。
- `degeneracy.enable=false` 时热路径仅多一次 if 判断，行为与基线数值等价。

**config/mid360.yaml 新增配置段**：

```yaml
degeneracy:
    enable: false
    debug_iterations: false
    threshold_t: 0.02
    threshold_r: 0.02
    ema_alpha: 0.5
    score_enter: 0.4
    score_exit: 0.2
    min_enter_frames: 3
    min_exit_frames: 5
```

### 4.3 外部几何代理检测器（`lio_evaluation/src/degeneracy_proxy.cpp`）

- 订阅 `/cloud_registered`（世界系注册点云）+ `/Odometry`。
- 自维护 voxel（0.5m）+ 时间剪枝（30s）局部地图 → `KdTreeFLANN` kNN(k=5) → PCA 平面拟合
  （`λ3 < 0.2·(λ1+λ2)` 判定平面）→ 以**帧质心**中心化构建转动 Jacobian（消除大平移偏置）。
- 输出与内嵌检测器**同口径**的 `DegeneracyScore`，发布 `/lio/degeneracy_score_proxy`。
- 定位：验证内部 Hessian 分数与外部点云几何趋势是否一致，**不是独立真值检测器**
  （`/cloud_registered` 本身已依赖 FAST-LIO 位姿估计）。

### 4.4 在线采集与资源监控（M4）

**`recorder_node.py`**：统一落盘（fast_lio 内部只发布不写盘，避免磁盘 IO 混入性能测量）：
- TUM 轨迹：`/gt_odom → groundtruth.txt`、`/Odometry → fastlio.txt`、可选 `/xxx → liosam.txt`
- 退化分数：`/lio/degeneracy_score → degen_exact.csv`、`/lio/degeneracy_score_proxy → degen_proxy.csv`
- IEKF 迭代：`/lio/degeneracy_iterations → degen_iterations.csv`

**`monitor_node.py`**：psutil 每 1s 采样 `fastlio_mapping` 的 CPU/RSS/VMS/线程数 → `resource.csv`；
同时按 `/Odometry` 消息间隔统计帧耗时 → `frametime.csv`；离线合并为 `runtime.csv`。


### 4.5 离线评测 `compute_metrics.py`

流水线（全离线，无 ROS 依赖）：

```text
groundtruth.txt + fastlio.txt
  → GT 按 est 时间戳线性插值(位置) + slerp(姿态)       # 时间对齐
  → SE(3) Umeyama 对齐 (evo Trajectory.align)          # 坐标对齐 (camera_init vs map)
  → APE / RPE (evo Python API) → ATE/RPE 统计
  → evo_ape / evo_rpe CLI --save_results → ate_result.zip / rpe_result.zip
  → frametime.csv + resource.csv 合并 → runtime.csv
  → degen_exact.csv + degen_proxy.csv → 退化统计 + 双检测器一致性
  → result.yaml
```

双检测器一致性（不设硬性 corr 阈值，综合多指标）：
`Pearson / Spearman / RMSE / event_overlap（退化时段重合率）/ detection_delay_s（进入退化时间差）`。

`result.yaml` 汇总字段：

```yaml
experiment / trajectory {n_gt, n_est, duration_s, length_m, dt_median_s}
ate {rmse_m, mean_m, median_m, max_m, align: umeyama_se3}
rpe {delta_m, rmse_m, mean_m, median_m, max_m}
degeneracy {exact, proxy, consistency{pearson, spearman, rmse, event_overlap, detection_delay_s}}
runtime {loop_time_ms{mean,max,p99}, cpu_percent{mean,max}, rss_mb{mean,max}, vms_mb}
directional {pos_err_rms_m{x,y,z}, weak_dir_err_rms_m, axis_error_growth_m, max_growth_axis, ...}
```

### 4.6 实验编排 `run_experiment.py`

### 4.7 受控退化场景（M5）

受控退化场景是**实验夹具**，不再作为包内静态 world 驻留：由 `generate_worlds.py`
在实验期生成到实验目录（`run_experiment.py --scenario <name>`），生成后自动自检
（XML 合法性 + 必须存在带碰撞的 ground_plane），运行期再由健康门禁验证
（世界真正加载 / 机器人落在地面 / 雷达有点云）。目的是从"找退化的地图看现象"
升级为"人为控制几何来验证 observability theory"：

| 场景 (--scenario) | 设计意图 | 预期退化 |
|---|---|---|
| `normal_room` | 12×12m 房间 + 4 柱 + 家具 | 无（健康基线） |
| `corridor` | 40m × 2.5m × 3m 长直走廊 | longitudinal translation 弱约束 |
| `single_plane` | 单一 30×10m 竖直平面 | plane degeneration |
| `open_ground` | 仅地面 | 只余 ground plane 弱约束 |

### 4.8 weak direction vs GT 方向误差对照（M6）

`directional_analysis.py` 建立"内部观测退化方向 ↔ GT 实际误差方向"的联系：

```text
groundtruth.txt + fastlio.txt
  → SE(3) 对齐 + 时间插值
  → 逐帧位置误差 e_t ∈ R³ (x/y/z) + 姿态误差角
  → 取 degen_exact.csv 每帧 weak_direction（H6 最小特征值特征向量）
  → 投影 e_weak = w[0:3]·e_t（归一化后）
  → 统计: 各轴误差 RMS、weak 方向误差 RMS、各轴误差增长、max_growth_axis
  → 出图 directional_error.png（|e_x|,|e_y|,|e_z|,|e_weak| + score 叠加）
  → 追加 result.yaml 的 directional 字段
```

若 corridor 的 weak direction（沿走廊纵向）对应的 GT 误差增长最显著，即建立了
"观测退化方向"与"实际误差方向"的强关联 —— 这是 P1 最有说服力的验证。

### 4.10 地图清理与加载防回归（本次会话修复）

**问题现象**：`run_experiment.py all --world normal_room.world` 时小车初始化后无限坠落、
FAST-LIO 全帧 `No Effective Points!`、里程计发散（z→19 万 m）、ATE≈57 km。

**根因**（`logs/gazebo.log` 实证）：
```text
[Wrn] File or path does not exist [.../install/get_urdf/share/get_urdf/worlds/normal_room.world]
[Err] Could not open file[...]
[Wrn] Falling back on worlds/empty.world        ← 无地面 → 无限坠落
```
- P1 自动生成的 4 个 world（normal_room/corridor/single_plane/open_ground）在 8/26 19:32
  才加入 `src/get_urdf/worlds/`，而 `get_urdf` 最后一次构建是 8/26 16:17 →
  **install 目录只有 P0/P0.1 的 5 个地图**，4 个新 world 从未被安装；
- launch 解析的是 `install/.../worlds/` 路径，找不到文件时 Gazebo **静默回退 `empty.world`**，
  无地面 → 机器人无限坠落，且不报致命错误，导致实验"看起来在跑、实际全废"。

**修复（本次）**：
1. **删除** 未经端到端验证的 P1 自动生成 world 与不满足需求的 `hospital_two_floors`，
   包内只保留 4 个确认地图（test_world / normal_indoor / bookstore / hospital）；
2. 受控退化场景改为**实验期生成夹具**：`run_experiment.py --scenario <name>` 用
   `generate_worlds.py` 生成到实验目录（自检 XML + ground_plane），不再驻留包内；
3. **防回归**：`get_urdf_launch.py` 启动前校验 world 文件存在（缺失即报错退出，
   不再静默回退 empty.world）；`run_experiment.py` 加地图白名单 + install 存在性校验
   + 运行时健康门禁（/gt_odom 落地 + 雷达有点云 + gazebo.log 无回退）。

**验证中发现并修复的额外问题**：
- **静态机器人**：实验中小车静止 → ATE/RPE 无意义，RPE(delta=1m) 还会崩溃。
  新增 `drive_node.py` 脚本化运动驱动（前进→掉头→返回，默认开启，`--no-drive` 关闭）。
- **孤儿 gzserver**：上一实验的 gzserver 残留占用 11345 端口 → 新 gazebo 连到旧世界，
  spawn 报 "Entity already exists"。`run-online` 启动前与 `_stop_all` 均加 pkill 兜底。
- **FAST-LIO 提前启动**：大场景模型未加载完时 FAST-LIO 首帧注册到局部几何 → 立即发散
  （bookstore 首帧 z=923）。调整启动顺序：**先健康门禁（世界就绪）再启动 FAST-LIO**。
- **出生点被卡**：normal_indoor/bookstore 默认 (0,0) 会卡进家具 → 内置推荐出生位姿
  （normal_indoor: x=5.0（实测可正常落地），y/z 沿用原推荐；bookstore: x=-2.3 y=6.2 yaw=-1.72），
  并支持 `--x/--y/--z/--yaw` 覆盖；GT 位移过小时调整出生点或缩短驱动距离。
- **RPE 优雅降级**：`compute_metrics.py` 在轨迹过短（RPE 无 1m 配对）时不再崩溃，
  输出 `rpe: null` 并保留 ATE/directional 结果。

## 8. P2 计划（Error Attribution，误差归因）

**目标**：把"误差归因"做成可运行的 online 模块（rule-based，不上 ML）。

## 9. P3 计划（Degeneracy-aware FAST-LIO，自适应更新）

### 9.1 第一版：Adaptive LiDAR Weight（低风险）

- 退化严重时**降低 LiDAR measurement 对 IEKF correction 的权重**（`LASER_POINT_COV` 自适应放大），
  相对提高 IMU propagation 权重。
- 控制信号：P1 的 `is_degenerate`（已做 EMA + 滞后，稳定可用）。
- 基线/消融实验：同一 bag 跑 baseline / degen(只检测) / degen+adaptive 三组，对比 ATE/RPE。
- 预期：退化场景 ATE/RPE 下降，正常场景性能基本不变（验证"改进未破坏正常场景"）。

### 9.2 第二版：Directional Suppression（创新点）

- 不再整体降低 LiDAR 权重，而是**只抑制 weak observable direction 的 correction**：
  - 用 P1 保存的 `weak_direction`（完整 6DoF 特征向量）构造方向掩码；
  - 沿 weak direction 缩小 correction，保留 well-observed direction 的正常更新；
  - 例如走廊中纵向平移弱约束被限制，而横向与部分转动仍正常更新。
- 包装命名：**Observability-aware FAST-LIO**。

### 9.3 六层完整框架

```text
FAST-LIO baseline
  → Degeneracy Detection (P1 ✅)
  → LIO Health Monitor   (P1 已埋 geometry/matching 两路, P2 扩展 filter 路)
  → Error Attribution    (P2)
  → Adaptive Update      (P3)
  → Gazebo Ground Truth Evaluation (P1 已建闭环)
```

## 10. 风险与注意事项

1. **基线零侵入**：`degeneracy.enable` 默认 false；实验务必记录 `algo_mode` + git commit，防止 P2/P3 改动混入 baseline。
2. **理论口径**：所有文档/变量使用 geometric Hessian / measurement Hessian；消息注释已写明"仅反映 scan-to-map 几何约束"。
3. **weak_direction 坐标系**：`h_x` 前 6 列 = 平动(世界系) + 转动(body 系)，`weak_direction` 按此顺序保存，P3 方向抑制需与 state error 定义核对。
4. **受控场景阈值**：corridor 宽度/长度、single_plane 尺寸需在 M5 实测调优，用趋势验收不设固定分数。
5. **bag 回放**：必须 `--clock` + `use_sim_time:=true`（编排已内置）。
6. **数值等价验证**：只比较轨迹/统计层（极小 tolerance），不做 byte-level。
