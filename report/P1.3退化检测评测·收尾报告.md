## 1. 背景与目标

用户在长走廊退化场景（`corridor_run1` bag）上分别用 **baseline** 与 **degen** 各跑了一次回放，得到：

| 运行 | ATE rmse | RPE rmse |
|---|---|---|
| baseline（exp_018） | 0.0636 m | 0.0291 m |
| degen（exp_019） | 0.0472 m | 0.0230 m |

表面看 "degen 比 baseline 好约 1.6cm"。但 P1 的退化检测被设计为**零侵入**（只检测不改状态更新），因此需要回答三个问题，即本报告的 A-B-C：

- **A（数值等价）**：这 1.6cm 是"退化检测带来的提升"，还是**回放本身的非确定性噪声**？
- **B（阈值标定）**：exact 检测器在该走廊 `degraded_ratio=0.0%`（完全不报退化），是走廊不退化，还是阈值太严？
- **C（弱方向）**：exact 的弱方向≈z（竖直）而非理论预期的纵向 x，为什么？误差是否真的沿弱方向增长？

## 2. A. 数值等价验证：差异是回放噪声，不显著

### 2.1 方法

同一 `corridor_run1` bag，`--algo baseline` / `--algo degen` 各回放 2 次（加上用户原跑共 3 组/模式）：

```bash
cd /home/db2412/Lidar_nav2_ws && source install/setup.bash
python3 src/lio_evaluation/scripts/run_experiment.py all --algo baseline --bag data/bags/corridor_run1 --duration 60
python3 src/lio_evaluation/scripts/run_experiment.py all --algo degen    --bag data/bags/corridor_run1 --duration 60
```

### 2.2 结果

| 运行 | 模式 | ATE(m) | RPE(m) | 轨迹长(m) | n_est |
|---|---|---|---|---|---|
| exp_018 | baseline | 0.0636 | 0.0291 | 49.70 | 530 |
| exp_020 | baseline | 0.0484 | 0.0265 | 49.74 | 534 |
| exp_021 | baseline | 0.0601 | 0.0267 | 49.06 | 521 |
| exp_019 | degen | 0.0472 | 0.0230 | 49.75 | 528 |
| exp_022 | degen | 0.0481 | 0.0267 | 49.42 | 524 |
| exp_023 | degen | 0.0486 | 0.0276 | 49.74 | 526 |

| 统计 | baseline | degen |
|---|---|---|
| ATE 均值 ± 标准差 | 0.0574 ± 0.0080 | 0.0480 ± 0.0007 |
| ATE 范围 | [0.0484, 0.0636]（极差 **0.0152**） | [0.0472, 0.0486]（极差 0.0014） |
| Welch t 检验 | **t=2.04, p=0.177（p>0.05，不显著）** | |

### 2.3 结论

- **baseline 自身组内极差（0.0152m）大于组间均值差（0.0094m）**，且 degen 的典型值（0.048）落在 baseline 的下端范围内；
- 统计上（n=3，Welch t，p=0.177）**不能认为 degen 比 baseline 更准**；
- 代码层面复核 `laserMapping.cpp`：`compute_geometric_hessian()` 在 IEKF 更新**之后**只读 `ekfom_data.h_x` 计算几何 Hessian，`is_degenerate` 仅发布、从不回写状态 → **零侵入，开启检测理论上不应改变轨迹**；
- 两次回放本身也非确定性（n_est 521~534、轨迹长 49.06~49.75m、loop_time max 110ms vs 200ms）→ 差异来源是**回放时序抖动**，不是算法差异。

> 附带发现：**退化检测指标自身也有噪声** —— proxy `degraded_ratio` 在三次 degen 回放中为 5.9%/9.4%/9.4%，随回放时序波动。因此"检测是否触发"也要以多次回放为准。

## 3. B. exact 阈值标定：走廊几何上几乎全程退化，P1 阈值太严

### 3.1 方法

对 `mid360.yaml` 的 `degeneracy.threshold_t` 做 0.02（P1 默认）→ 0.10 → 0.15 三档，同一 bag 回放：

```bash
# prepare 后改实验目录内的 mid360.yaml（不改源配置）
sed -i 's/threshold_t: 0.02/threshold_t: 0.10/' data/experiments/experiment_024/mid360.yaml
python3 src/lio_evaluation/scripts/run_experiment.py replay data/experiments/experiment_024 --bag data/bags/corridor_run1
python3 src/lio_evaluation/scripts/run_experiment.py eval data/experiments/experiment_024
```

### 3.2 结果

| threshold_t | exact degraded_ratio | exact mean_score | ATE(m) |
|---|---|---|---|
| 0.02（exp_022） | **0.0%** | 0.0007 | 0.0481 |
| 0.10（exp_024） | **99.6%** | 0.536 | 0.0484 |
| 0.15（exp_025） | **99.6%** | 0.691 | 0.0567 |

- `fastlio.log` 在阈值放宽后出现 `[Degeneracy] ENTER: score=0.738 trans_ratio=0.0283 rot_ratio=0.0317`；
- 打分公式：`score = max(0, 1 − trans_ratio/threshold_t, 1 − rot_ratio/threshold_r)`，EMA+滞回状态机（进入>0.4 连续 3 帧）。

### 3.3 结论

- 该走廊 `trans_ratio≈0.047`（且局部低至 0.028），**几何约束确实很弱**；`threshold_t=0.02` 使 `1−0.047/0.02 < 0` → score 恒 0 → **完全漏检**；
- 阈值放到 0.10 或 0.15 后 exact 立刻报出 **99.6% 帧退化** —— 说明"检测器不报"不是"走廊不退化"，而是 **P1 默认阈值比实际量级严了 5~7 倍**；
- **阈值不影响轨迹**（0.02/0.10 两档 ATE 均为 0.048，符合零侵入）；0.15 档 ATE=0.057 仍在回放噪声范围；
- 正式阈值建议：**corridor 类场景 `threshold_t` 取 0.10~0.15**（P1 报告局限表"corridor 漏检，0.02→0.10~0.15"得到实测确认）。

## 4. C. 弱方向分析：为什么是 z？误差是否沿弱方向增长？

### 4.1 弱方向构成（exp_024 exact 逐帧弱特征向量）

| 弱方向轴 | 占比 |
|---|---|
| **z（竖直）** | **81.9%** |
| x（纵向） | 18.1% |
| y（横向） | 0.0% |

特征值谱：`e0=15, e1=24, e2=71, e3=1017, e4=2303, e5=16742`；e0（弱方向对应）沿时间稳定在 p10/p50/p90 = 10.7/15.8/19.0，**持续弱**；平动块（e0~e2）整体比转动块（e3~e5）小两个数量级 → 转动约束强、平动约束弱。

### 4.2 几何原因（bag 点云实测）

从 `corridor_run1` bag 直接解析 `/livox/lidar` 点云（rosbags）：

| 帧 | 点数 | 地面点(z<−0.15) | z>0.5(上半区) | y 范围 |
|---|---|---|---|---|
| 60 | 7404 | 6.9% | 57.2% | [−1.58, 1.65] |
| 400 | 7398 | 6.7% | 56.6% | [−1.38, 0.98] |
| 800 | 7375 | 6.4% | 53.8% | [−1.59, 0.76] |

- 雷达垂直视场 **−7°~+52°**（约 89% 朝上）：在 0.8m 窄走廊中，两侧墙面占满视场（法向≈±y）→ **y（横向）约束最强，从不成为弱方向**；
- 地面只在底部 −7° 条带可见，仅占 **~6% 点** → **z（竖直）约束最弱**；
- x（纵向）约束来自走廊尽头与沿途特征，仅 18% 帧成为弱方向。

### 4.3 误差是否沿弱方向增长？

（Umeyama 对齐后逐帧误差，插值到 degen 时间戳）

| 指标 | 数值 |
|---|---|
| 总误差 mean | 0.045 m |
| 弱方向投影 mean | 0.026 m（**58%**） |
| 垂直分量 mean | 0.033 m |
| Pearson(trans_ratio, \|err\|) | **−0.150**（弱负相关） |
| Pearson(trans_ratio, d\|err\|/dt) | 0.041（≈无） |
| trans_ratio<p50 的 mean\|err\| | 0.046 m |
| trans_ratio≥p50 的 mean\|err\| | 0.044 m |

### 4.4 C 结论（核心发现）

1. **弱方向确实是 z**：0.8m 窄走廊 + 朝上视场 → 墙强约束 y、地面点过少 → z 约束最弱（81.9% 帧）。这复现了 P1 corridor 的 `max_growth_axis=z` 异常，且是 50m 长走廊、数据确凿的几何事实。
2. **但"退化"≠"误差大"**：exact 在阈值 0.10 下报 99.6% 帧退化（trans_ratio≈0.047 极低），而 ATE 仍只有 **~5cm**，且误差仅 58% 沿弱方向、与 trans_ratio 几乎不相关（r=−0.15）。
3. **原因**：FAST-LIO 的 IMU 传播 + 其余自由度（墙对 y/转动）的强约束把漂移约束在厘米级；几何观测病态 ≠ 滤波发散。**这正说明"退化检测"与"误差增长"之间不能划等号**——检测报的是"几何可观测性弱"，误差大小还取决于滤波器鲁棒性。

## 5. 综合结论（P1 系列收尾）

1. **回放评测闭环可信**：同一 bag 的 baseline/degen 对比可复现、可出全套指标；
2. **"degen 比 baseline 准 1.6cm"不成立**：差异在回放噪声内（p=0.177），且检测器零侵入，理论上不改变轨迹；
3. **exact 检测器在 corridor 漏检是阈值问题，不是算法问题**：`threshold_t` 0.02→0.10/0.15 后检测率 0.0%→99.6%，建议正式标定到该区间；
4. **弱方向在 z 是场景几何的真实特性**（0.8m 走廊 + 朝上视场 + 地面点 6%），且**弱约束方向并不对应大误差**——对 P2 误差归因（geometry vs error 解耦）和 P3 方向抑制（只压弱方向更新）提供了明确前提：P3 应优先抑制 z 方向的弱 correction，但预期收益受限于当前误差本就不大。
