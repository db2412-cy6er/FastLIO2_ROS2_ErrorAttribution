## 1. 项目背景与目标

当前机器人仿真工程已经具备以下能力：

- FAST-LIO2 / Point-LIO 等 LiDAR-Inertial 里程计算法（已跑通）
- Livox MID-360 激光雷达仿真（`/livox/lidar`）
- IMU 仿真（`/livox/imu`）
- 差速小车底盘（`/cmd_vel` 控制）
- 机器人模型：`simple_car.urdf`（含 base_footprint、chassis、4 轮、livox_frame）

**原有问题**：启动 Gazebo 的地图（world）文件被写死为 `test_world.world`，机器人出生位姿写死；新增的室内地图 `normal_indoor.world`（源自 AWS RoboMaker Small House）无法通过 `ros2 launch` 正确加载模型与 mesh。

**本次 P0 目标**：让「环境地图可配置 + 机器人出生位姿可配置 + Gazebo 模型资源路径自动配置」，且不破坏原有数据链。

## 7. 关键技术细节

### 7.1 world 参数解析

```python
# PathJoinSubstitution + FindPackageShare 自动拼接，不硬编码绝对路径
world_file = PathJoinSubstitution([
    pkg_share, 'worlds', _world_filename(LaunchConfiguration('world'))])
```

`_world_filename()` 通过 `PythonExpression` 实现：`world` 参数省略 `.world` 后缀时自动补全。

### 7.2 出生位姿传递

`spawn_entity.py` 中 **yaw 使用 `-Y`**（不是 `-yaw`），这是 gazebo_ros 的 argparse 定义：

```python
arguments=[
    '-entity', 'simple_car',
    '-topic', 'robot_description',
    '-x', LaunchConfiguration('x'),
    '-y', LaunchConfiguration('y'),
    '-z', LaunchConfiguration('z'),
    '-Y', LaunchConfiguration('yaw'),
]
```

`z` 默认 `0.30` 而非 `0`：因为 URDF 原点不一定在轮胎接地点，略高于地面让 Gazebo 物理引擎自然落地。

### 7.3 GAZEBO 环境变量自动配置

`SetEnvironmentVariable` 是 ROS2 Humble 标准动作，写入 `launch context.environment`（不是直接改 `os.environ`），因此**必须放在 Gazebo `ExecuteProcess` 之前**。实现时保留原值（prepend）：

```python
SetEnvironmentVariable(name='GAZEBO_MODEL_PATH', value=[
    gazebo_models_path,                       # <root>/models
    ':', EnvironmentVariable('GAZEBO_MODEL_PATH', default_value=''),
])
SetEnvironmentVariable(name='GAZEBO_RESOURCE_PATH', value=gazebo_resource_parts)  # <root>:<media>:<原值>
```

> ⚠️ 注意：`EnvironmentVariable(...)` **必须带 `default_value=''`**，否则环境变量不存在时会抛出 `SubstitutionFailure` 导致 launch 直接报错。

### 7.4 Gazebo media 路径（本次最重要的修复）

**现象**：`normal_indoor.world` 模型/mesh 已能加载，但 gazebo 进程崩溃，报错链：

```text
RTShaderSystem: Unable to find shader lib ... Have you sourced <prefix>/share/gazebo/setup.bash?
→ RenderEngine: Failed to initialize scene
→ GLWidget: could not create a scene
→ gzclient: 断言 "px != 0" 失败（Camera 为空指针）
```

**根因**：`/opt/ros/humble/setup.bash` **不会**设置 Gazebo 的媒体资源路径；`/usr/share/gazebo/setup.sh` 才会把 `/usr/share/gazebo-11`（含 `media/rtshaderlib` 着色器库）写入 `GAZEBO_RESOURCE_PATH`。缺失时 OGRE 无法初始化渲染场景 → gzclient 崩溃。

**修复**：`_find_gazebo_media_path()` 运行时探测 `/usr/share/gazebo-11`（或 `/usr/share/gazebo`），把含 `media/` 的路径自动加入 `GAZEBO_RESOURCE_PATH`：

```text
GAZEBO_RESOURCE_PATH = <gazebo_resource_root> : /usr/share/gazebo-11 : <原值>
```

### 7.5 启动日志（排错入口）

```python
OpaqueFunction(function=_check_and_log)
```

`_check_and_log` 输出：

- **现象**：模型加载正常、机器人能 spawn，但 gazebo 进程崩溃（见 7.4 错误链）。
- **定位**：隔离实验证明，仅在 `GAZEBO_RESOURCE_PATH` 中加入 `/usr/share/gazebo-11` 后 gzclient 不再崩溃。

## 11. 注意事项与排错

### 11.1 Package not found

```text
Package 'get_urdf' not found: searching: ['/opt/ros/humble']
```

**原因**：当前终端没有 source 工作空间环境。

**解决**：

```bash
cd ~/Lidar_nav2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

### 11.2 Gazebo address already in use

```text
EXCEPTION: Unable to start server[bind: Address already in use]
```

**原因**：上一个 Gazebo 进程残留（或手动 `gazebo --verbose` 后未关闭）。

**解决**：

```bash
pkill -9 gzserver
pkill -9 gzclient
```

### 11.3 normal_indoor 地图模型不显示但小车正常

**原因**：`GAZEBO_MODEL_PATH` 未包含 Small House 模型的 `models/` 目录。

**解决**：确认 `gazebo_resource_root` 默认值指向正确路径（`.../small_house/extracted`），或通过命令行覆盖：

```bash
ros2 launch get_urdf get_urdf_launch.py \
  world:=normal_indoor.world \
  gazebo_resource_root:=/your/custom/path/extracted
```

### 11.4 gzclient 崩溃（Failed to initialize scene）

**原因**：`GAZEBO_RESOURCE_PATH` 缺少 `/usr/share/gazebo-11`（Gazebo 自带 media/ 着色器库）。

**修复**：`_find_gazebo_media_path()` 已自动探测并加入，如仍有此问题，请确认 `/usr/share/gazebo-11/media/` 存在。若使用不同版本 Gazebo（如 Gazebo 9），需修改 `_find_gazebo_media_path()` 中的候选路径。

### 11.5 端口冲突与孤儿 gzserver

手动 `gazebo --verbose` 测试后，gzserver 可能残留（无 gzclient 窗口），持续占用端口 11345。每次实验前可通过以下命令确认：

```bash
ss -ltnp | grep 11345
```

若端口被占用，`pkill -9 gzserver` 清理。

### 11.6 需要外部设置的环境变量

`normal_indoor.world` 引用的模型位于非工程目录，若手动 `gazebo --verbose` 测试需在终端设置：

```bash
export SMALL_HOUSE="$HOME/gazebo_world_sources/Dataset-of-Gazebo-Worlds-Models-and-Maps/worlds/small_house/extracted"
export GAZEBO_MODEL_PATH="$SMALL_HOUSE/models:$GAZEBO_MODEL_PATH"
export GAZEBO_RESOURCE_PATH="$SMALL_HOUSE:$GAZEBO_RESOURCE_PATH"
```

> 通过 `ros2 launch` 启动时，launch 文件会自动设置以上路径（使用 `gazebo_resource_root` 参数），无需手动 export。
