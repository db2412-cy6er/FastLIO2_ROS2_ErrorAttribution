## 4. 具体改动说明

### 4.1 修复 `aws_robomaker_retail_Spotlight_01` 大小写 bug

`bookstore.world` 会引用 `model://aws_robomaker_retail_Spotlight_01`，该模型 `model.sdf` 原引用：

```xml
<uri>file://models/aws_robomaker_retail_Spotlight_01/meshes/aws_Spotlight_01_collision.DAE</uri>
<uri>file://models/aws_robomaker_retail_Spotlight_01/meshes/aws_Spotlight_01_visual.DAE</uri>
```

但实际文件名是小写 `aws_spotlight_01_collision.DAE` / `aws_spotlight_01_visual.DAE`，Linux 大小写敏感会导致 mesh 加载失败。已改为与实际文件一致的小写引用。

### 4.2 移除 bookstore 内置机器人

原 `bookstore.world` 尾部内置了一台 `turtlebot3_waffle_pi`：

```xml
<include>
  <pose>-2.3 6.2 0.0 0.0 0.0 -1.72</pose>
  <uri>model://turtlebot3_waffle_pi</uri>
</include>
```

本项目使用 `simple_car`（由 `spawn_entity.py` 从 `/robot_description` 生成），为避免场景出现第二台机器人，已将该 include 注释掉。原位置 `x=-2.3 y=6.2 yaw=-1.72` 可作为 bookstore 出生点参考。

### 4.3 模型合并与去重

- Bookstore 压缩包内的 `turtlebot3_burger / turtlebot3_waffle / turtlebot3_waffle_pi / turtlebot3_world`（约 78 MB）未复制，只保留 34 个 `aws_robomaker_retail_*` 模型。
- Hospital 四个分卷 `models_part1~4.zip` 顶层为 `models_partN/<模型>`，已规范化合并为 `models/<模型>/`；与 small_house / bookstore 重复的 `aws_robomaker_residential_*`、`aws_robomaker_retail_*` 模型跳过，保留已有版本。

## 5. 测试步骤（具体代码）

### 5.1 构建

```bash
cd /home/db2412/Lidar_nav2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select get_urdf --symlink-install --executor sequential
source install/setup.bash
```

> `--symlink-install` 让 `install/` 下的模型指向 `src/`，改动模型后无需重复复制；
> `--executor sequential` 限制并行度，避免高并发占用大量内存。

### 5.2 查看 launch 参数（确认资源根目录已内置）

```bash
ros2 launch get_urdf get_urdf_launch.py --show-args
```

期望看到 `gazebo_resource_root` 的默认值为 `FindPackageShare(pkg='get_urdf')`，不再是 `/home/db2412/gazebo_world_sources/...`。

### 5.3 启动各场景（加载小车）

```bash
# 第 2 个地图：室内住宅
ros2 launch get_urdf get_urdf_launch.py world:=normal_indoor

# 第 3 个地图：书店（参考出生点取自原 turtlebot3 位置）
ros2 launch get_urdf get_urdf_launch.py world:=bookstore \
    x:=-2.3 y:=6.2 z:=0.30 yaw:=-1.72

# 第 4 个地图：医院（单层）
ros2 launch get_urdf get_urdf_launch.py world:=hospital

# 医院（双层，仅作研究/退化场景，注意出生点需实测）
ros2 launch get_urdf get_urdf_launch.py world:=hospital_two_floors
```

> 出生位姿参数 `x / y / z / yaw` 可任意覆盖；`z` 建议保持 `0.30`，由物理引擎自然落到地面。

### 5.4 验证话题（新开终端）

期望出现：`/livox/lidar`、`/livox/imu`、`/odom`、`/gt_odom`、`/cmd_vel`、`/clock`。

## 7. 注意事项与待办

### 7.1 出生点需实测

默认 `x=0 y=0 z=0.30` 在 hospital 中可能落在护士站/家具上，需在真实启动后按 `x / y / yaw` 调整。bookstore 可先用 `x=-2.3 y=6.2 yaw=-1.72`。

### 7.2 两个未引用的上游坏模型（保留但无害）

- `models/Extinguisher cabinet`：目录名含空格，内部 `model://Extinguisher` 引用不完整；
- `models/HospitalPillow`：缺 `meshes/HospitalPillow_Col.obj`。

两者均**未被任何 world 引用**，不影响加载；如需彻底清理可自行删除。

### 7.3 后续待办

1. 为 bookstore / hospital 实测并固化推荐出生位姿（可写入 README 或 launch 默认值）。
2. 生成 bookstore / hospital 对应的 2D 地图（`.yaml`/`.pgm`）与先验点云（`.pcd`），用于 Nav2 / KISS-Matcher 重定位。
3. `hospital_two_floors.world` 因双层在同平面坐标上重叠，不建议直接使用单张 2D Nav2 地图，需另做分层方案。
