## 1. 目标与范围

P3 第一版实现 **Adaptive LiDAR Weighting**（整体自适应激光权重），是 P1 报告 §9.1 预定的
低风险路线：**只改变传入 `update_iterated_dyn_share_modified()` 的 measurement covariance
（`R`），不修改 `esekfom.hpp` 内部 Kalman update 结构**。

一句话机制：
> 把编译期常量 `LASER_POINT_COV` 换成运行时变量 `lidar_meas_cov_`；当退化检测/误差归因
> 判定"几何约束弱"或"匹配失败"时按严重程度动态放大 `R`，降低本帧 LiDAR correction 的权重，
> 相对提高 IMU propagation 的权重。

**明确不做**（本版）：directional suppression（沿弱方向抑制）——它是整体权重方法的能力边界
被量化之后的下一个阶段。

### 1.1 为什么整体权重是"能力边界"实验
scalar `R` 放大只能改变 LiDAR 与 IMU 的相对信任，**不能创造原本不存在的几何约束**。
因此本版的预期结论框架是：

| 场景 | 预期 | 意义 |
|---|---|---|
| matching fault（激光坏了）| 明显抑制错误 correction | **本版主要受益场景** |
| corridor（几何退化但 ATE 小）| 基本无损 | 验证"几何 mild 降权不破坏" |
| single-plane（严重退化 7.4m）| 改善有限甚至变差 | **全局权重方法的能力边界**，为 directional suppression 立项 |

## 2. 设计（对应评审修订）

### 2.1 one-frame delayed feedback controller（评审 R3/R9/R10）
- 本帧 IEKF 使用**上一帧** update 收敛后 `degen_data` 算出的 scale（滞后 1 帧 ~0.1s）；
- **对持续性 degradation 有效**；**对 first-frame abrupt fault（单帧突发 outlier）不具备提前保护能力**——
  第 100 帧突发大量 outlier 时，第 100 帧仍使用第 99 帧的健康 covariance；
- 代价规避：不侵入 `esekfom.hpp`（`R` 本就是函数参数，`laserMapping.cpp` 单点替换）；
- 后续（不阻塞 v1）：轻量 current-frame emergency gate（进入 IEKF 前的 raw point count /
  dropout ratio），残差与 Hessian 仍走 previous-frame feedback。

### 2.2 控制信号：双通道 severity（评审 R2/R4/R13）
- **geometry 路（mild）**：完整复刻 P2 `attribution_rules.severity_geometry`
  （`score/trans_ratio/rot_ratio` 的 margin 组合，阈值 = P1.3 冻结值），上限 `max_geom_scale`（默认 2~10）；
- **matching 路（aggressive）**：完整复刻 P2 `attribution_rules` 的 matching severity
  （`feats/ratio/residual_p90/相对骤降` 全公式与冻结阈值），上限 `max_match_scale`（默认 20~100）；
- **IMU_LOW_EXCITATION 不进入 control channel**（评审 R1，理论修正）：
  > 低激励描述机器人运动状态缺乏 excitation，影响 bias 可辨识性/部分状态可观性/系统 observability，
  > **不意味着 IMU 瞬时角速度与加速度测量失效**。当几何退化 + IMU 低激励并存时，继续大幅降低
  > LiDAR 权重存在更高纯 IMU drift 风险；因此低激励仅作为风险监测信号保留（health/日志），不触发降权。

### 2.3 保护机制（评审 R20/R21/R22）
- **下限恒为 baseline**：`applied_scale ≥ 1.0`，绝不允许把 `R` 调到比 `LASER_POINT_COV` 更小；
- **上限**：`max(max_geom_scale, max_match_scale)`；
- **fast attack / slow release**：`attack_alpha=0.5`（快速进入降权）、`release_alpha=0.1`（缓慢恢复），
  替代单一 EMA——避免"进入慢、退出快"的权重震荡；
- **正反馈防护**：连续高 scale（`> high_scale_warn_th=3.0`，默认仅 matching 或大 geometry 配置可触发）
  持续 5s 打 WARN 告警，防"匹配差→降权→更漂→匹配更差"循环无限维持；
- **max 而非相乘**：`final_scale = max(geom, match)`，避免几何×匹配重复惩罚导致极端 covariance inflation。

### 2.4 参数单一事实源（评审 R4/R18/R19）
- **唯一参数源 = `mapping.launch.py` launch dict**（`adaptive_*` 参数，默认全关 = 零侵入）；
- **不新增 `mid360.yaml` 的 adaptive 段**（不复制 P2 health 段的"文档配置"反模式）；
- `run_experiment.py` 在每次实验把 resolved adaptive 参数写入 `<exp_dir>/config.yaml` 快照；
- 数值口径：`lidar_meas_cov` 叫 **measurement covariance scale / LiDAR measurement weight**，
  **不是真实物理噪声**（`R` 是 residual covariance/variance 量级，非点云标准差）。

### 2.5 公式（D3）
```
g_sev = severity_geometry (复刻 P2)           ∈ [0,1]
m_sev = severity_correspondence (复刻 P2)     ∈ [0,1]
geometry_scale = 1 + (max_geom_scale - 1) * g_sev      # detected 本帧
matching_scale = 1 + (max_match_scale - 1) * m_sev     # detected 本帧
final_scale    = max(geometry_scale, matching_scale)   # detected 本帧 (EMA 前)
applied_scale  = EMA(final_scale; attack_alpha, release_alpha)  # 上一帧 detected → 本帧
lidar_meas_cov = LASER_POINT_COV * applied_scale       # 传入 update_iterated_dyn_share_modified
```

### 2.6 LioHealth.msg 扩展（评审 R15/R16/R17）
新增 5 字段，**时间语义在消息注释与 CSV 表头中明确标注**：
```
lidar_meas_cov   # applied：本帧 IEKF 实际使用的 measurement covariance (上一帧 severity 决定)
geometry_scale   # detected：本帧几何路 scale
matching_scale   # detected：本帧匹配路 scale
final_scale      # detected：本帧 max(geom, match) (EMA 前)
adaptive_active  # detected：final_scale > 1+eps
```
旧 bag 兼容：canonical bag 只存原始 3 topics（lidar/imu/gt），replay 时重新生成新 `/lio/health`，
消息接口升级不影响核心实验 bag。

## 4. P3.2 标定（corridor_run1，标定集）

### 4.1 网格与结果
| 组 | 配置 | 实验 | ATE rmse (m) | 备注 |
|---|---|---|---|---|
| C1 基线 | degen-only | exp_054 | **0.052** | |
| C1 + adaptive | geom=2 | exp_055 | 0.109 | 变差 |
| C1 + adaptive | geom=5 | exp_056 | 0.100 | 变差 |
| C1 + adaptive | geom=10 | exp_057 | 0.078 | 变差 |
| C3 基线 | degen-only | exp_058 | **1.064** | max 3.64 |
| C3 + adaptive | match=20（无保护）| exp_059 | **10.47** | 发散 |
| C3 + adaptive | match=50（无保护）| exp_060 | 4.97 | 发散 |
| C3 + adaptive | match=100（无保护）| exp_061 | 7.52 | 发散 |

> C1 干净段（无 fault）geometry 降权一致性变差（~2 倍）；C3 连续 fault 段 matching
> 降权**灾难性发散**。单次运行，结论定性。

### 4.2 关键机制发现：正反馈循环（评审 R22 实证）
exp_059（match=20 发散）的 health 时间序列：
| 段 | effective_feature_num | matching_scale | lidar_meas_cov |
|---|---|---|---|
| clean0-20（正常）| 421 | 1.17 | 0.0018 |
| dropout20-30（fault）| 183 | 4.94 | 0.0059 |
| clean30-40（**无 fault**）| 266 | 2.94 | 0.0034 |
| clean50-60（**无 fault**）| 250 | 12.05 | 0.0122 |
| clean65-75（**无 fault**）| **102** | **15.89** | 0.0162 |

链条：**fault 降权 → IMU 漂移 → 无 fault 段的 scan-to-map 失配（feats 骤降）→
被误判为"匹配失败" → 继续高 scale 降权 → 更漂**。clean65-75 段明明没有 fault，
matching_scale 却升到 15.9x——把干净激光当成坏的。

### 4.3 修复：降权时长上限（P3.1.1，`adaptive_max_downweight_duration_s=3.0s`）
连续降权超过 3s 强制 target=1 回 baseline，让激光重新主导，打破正反馈。
验证（C3 fault + match=20 带保护，exp_062）：
- ATE **1.39 m**（无保护 10.47m），max 6.18m；
- 不再灾难性发散，但仍略差于 degen-only 1.06m——**连续长 fault 期间"放弃激光"即使有上限也是净伤害**。

### 4.4 标定结论（P3 v1 能力边界）
> **仅依靠全局 LiDAR 权重调节（scalar R 放大）在标定集上两个通道均无收益**：
> - geometry 降权：corridor 虽几何退化但激光约束仍有效，整体降权削弱有效约束 → 变差；
> - matching 降权：连续 fault 期间降权 = 放弃激光 = IMU 漂移 → 无保护发散 / 有保护仍略差。
>
> 这正是"全局权重方法的能力边界"的量化证据：**geometry 的问题本质是方向性（不同方向
> 约束强弱不一致），必须用 directional suppression 处理；matching 的问题是持续性
> （长 fault 需要别的机制，如 robust matching / 失效时段冻结），不能靠整体降权**。

### 5.2 结论（P3 v1 定论）
> **正常场景（B）零影响**：adaptive 全程未触发（scale 恒 1，cov 恒 baseline），
> 结果与 degen 完全一致——"改进未破坏正常场景"✓。
>
> **几何退化场景（A/C）整体降权无收益甚至有害**：
> - corridor（A）：ATE 0.0376→0.0366，噪声内无差异（仅 RPE/final drift 轻微改进，量级 cm）；
> - single_plane（C）：1.757→7.95m，**变差 4.5 倍**——单面墙只有法向弱约束，整体降权连它一起削弱。
>
> **匹配故障场景（D1/D2）整体降权确定性有害**：
> - holdout（D1）：0.146→2.10m（变差 14×）；stress（D2）：1.07→9.29m（变差 8.7×，max 33m）；
> - fault 段 maxErr 放大 20 倍以上、recovery 从即时变成 30s+/不恢复；
> - 即使带 3s 降权时长上限保护（P3.1.1），连续 fault 期间"放弃激光 → IMU 漂移"仍是净伤害。

> **最终结论**：**仅依靠全局 LiDAR 权重调节（scalar R 放大）不能缓解退化/故障，在严重场景
> 确定性有害**。这从实验上完整回答了 P1 报告 §9.1 提出的问题，并给出两个明确的下一步：
> - geometry 退化的本质是**方向性**（不同方向约束强弱不一致）→ 必须 **directional suppression**；
> - matching 故障的本质是**持续性**（长 fault 不能靠"少信激光"，需 robust matching / 失效冻结
>   等机制）。
>
> P3 v1 的价值：**用 median-of-3 的严格数据量化了"整体权重方法的能力边界"，为后续
> directional suppression 提供了最强立项依据**——评审点 30 预期的最优结局。全部 30 runs
> （exp_063~092）+ 标定 9 runs（exp_054~062）数据可复现。

## 7. 结论

1. **P3 第一版 Adaptive LiDAR Weighting（整体 R 缩放）在严格 median-of-3 A/B 下，
   五个场景无一获得显著 ATE 改进**：正常场景零影响、corridor 无显著差异、
   single_plane 变差 4.5×、holdout/stress fault 变差 14×/8.7×。
2. **机制层面发现并修复正反馈循环**：降权→IMU 漂移→scan-to-map 失配→feats 骤降被误判
   匹配失败→继续降权（exp_059 实证 clean65-75 段 match_scale 15.9×）；降权时长上限
   （3s）能打破循环但无法消除"连续 fault 期间放弃激光"的本质伤害。
3. **回答了 P1 报告 §9.1 的问题**："仅依靠全局 LiDAR 权重调节能在多大程度上缓解退化？"
   —— **几乎不能，且在严重场景有害**。scalar 权重调节的能力边界 = 只对"轻微改善 RPE/
   final drift（cm 级）"有效。
4. **为 directional suppression 提供了量化立项依据**：geometry 退化是方向性问题（整体降权
   削弱有效约束）、matching 故障是持续性问题（降权放弃激光）——两者都不能靠 scalar R 解决。
