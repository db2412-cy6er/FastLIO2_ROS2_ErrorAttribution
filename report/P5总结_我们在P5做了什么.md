# P5 总结：我们在 P5 做了什么 (小白版)

> 这是 FAST-LIO 改进项目的最后一阶段 (P5)。前面 P1-P4 已经做完并冻结。

## 一句话总结

P5 想解决一个具体问题：**当激光雷达的匹配"明显错了"的时候，直接把这一帧扔掉，
不让错误的测量污染滤波器和地图**。我们把这个机制做出来了、验证它不误伤正常场景，
但也诚实发现：在持续故障下，主动"扔帧"反而比什么都不做更差。

## 我们用大白话做了什么

### 1. 想解决的问题

激光雷达定位（FAST-LIO）每 0.1 秒处理一帧点云。如果某一帧点云"对错了"（比如被
干扰、被遮挡、传感器故障），把错误信息喂给滤波器，位置估计就会跑偏。

之前的阶段试过"降低激光权重"（P3）和"抑制某个方向"（P4），都失败了。P5 换个思路：
**判断当前帧匹配质量，如果太差就直接拒绝这帧，不让它参与修正。**

### 2. 怎么实现的（约 5 行核心代码 + 状态机）

- 在 FAST-LIO 的核心滤波循环里，第一次完成"当前帧匹配"后，加一个检查点：
  - 匹配质量好 → 正常继续；
  - 匹配质量差（点变少且残差变大）→ 把状态恢复成"没见过这帧"的样子，
    本帧只用 IMU 数据推进，并且**不把这一帧点云加入地图**（防止污染）。
- 配了一个简单的"恢复状态机"：连续拒绝几帧就升级告警等级，但只要下一帧恢复正常
  就自动回到正常。

### 3. 我们做了哪些验证

- **仿真测试（synthetic）**：把门控逻辑单独拿出来测试，6 个场景全部通过。
- **真实回放实验**（同一批数据跑多次取中位数，因为 FAST-LIO 回放有随机性）：
  - ✅ **正常室内场景**：门控 0 误拒，轨迹和原版一模一样。
  - ✅ **"只有一面墙"的退化场景**：门控 0 误拒——这种"几何退化"不会触发
    "匹配失败"，两条问题路径分开了。
  - ⚠️ **持续故障场景**：门控拒绝了很多帧，但**最终轨迹反而比原版更差**
    （V5 故障：0.086m → 2.28m；stress 故障：1.84m → 10.7m）。

## 为什么持续故障下"扔帧"反而更差？

我们把原因查清楚了，这也是 P5 最重要的发现：

1. **原版 FAST-LIO 本身就很抗造**：试验用的故障强度（8% 乱点 / 80% 丢点 / 0.15m
   噪声）根本不足以让原版发散（V5 全程误差只有 8.6 厘米）。
2. **"扔帧"会引发连锁反应**：连续拒绝几帧 → 只有 IMU 在推进 → 位置漂移 →
   下一帧和地图对不上 → 又拒绝 → 更漂。这是个**自我强化的恶性循环**。
3. 这不是参数没调好，是机制本身的问题（我们试了很多参数组合都救不回来）。

## 这说明了什么（整个项目的最终结论）

把 P3、P4、P5 放在一起，结论非常一致：

> **对于 FAST-LIO 的"匹配错误"问题，任何"主动介入"的办法（降权 / 抑制方向 /
> 扔帧）都打不过原版滤波器自己扛。**
> 唯一真正有用的是 **P4 的"检测门"**（检测到匹配失败时阻止别的机制乱动），
> 以及 **P2 的"误差归因"**（把"几何退化"和"匹配错误"分清楚）。

## 那 P5 白做了吗？

不是。P5 留下了三件有价值的东西：

1. **证明"当前帧信号"是可靠的**：第一帧匹配的质量信号能 100% 区分正常/退化场景
   （0 误报），这为将来更聪明的方案（比如配合重定位）打下了基础。
2. **证明了"扔帧"这条路的边界**：以后再有人想做"帧级拒绝"，可以直接引用我们的
   负面结果，少走弯路。
3. **一个干净、可开关、零侵入的实现**：默认关闭，打开也不会破坏正常场景，
   随时可以复用。

## 项目全貌（P1 → P5）

| 阶段 | 做了什么 | 结论 |
|---|---|---|
| P1 | 检测"几何退化"（结构不够） | ✅ 有效 |
| P2 | 区分"几何退化 / 匹配错误 / IMU 弱" | ✅ 有效 |
| P3 | 匹配差时降低激光权重 | ❌ 证伪（恶性循环） |
| P4 | 抑制弱方向的修正 | ❌ 证伪（信息缺失无解）；但"匹配门"有效 |
| P5 | 匹配差时直接扔帧 | ⚠️ 机制可用 + 正常场景零侵入，但持续故障下反而不如原版 |

**最终结论**：FAST-LIO 原版的容错已经很好，"主动介入"的防护措施都难以超越它。
真正有价值的产出是**检测与归因能力**（P1/P2），而不是**控制干预**（P3/P4/P5）。
