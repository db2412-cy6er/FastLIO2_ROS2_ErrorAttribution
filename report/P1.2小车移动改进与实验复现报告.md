## 1. 本次改动的目标

P1 退化检测评测闭环在真实实验中发现两个影响"跑满 90s"的问题，本次迭代针对它们做了改进：

1. **小车盲目脚本驾驶，无避障** → 撞墙、卡死、翻车 → FAST-LIO 数据报废，`result.yaml` 的有效时长远小于 90s；
2. **Gazebo 里小车"一卡一卡"** → 由①撞墙后的 ODE 接触抖动、②虚拟机软件渲染（`svga_surface_destroy`）、③仿真 RTF<1 共同造成；
3. **需求补充**：①实验期走更多没走过的路（覆盖更多区域）；②支持 **WASD 手动遥控**录制 90s 数据。

## 3. 核心实现说明

### 3.1 drive_node：避障 + 漫游 + 平滑（默认参数）

```text
脚本漫游（wander）:  前进 3.2m (0.4 m/s × 8s) → 原地转 30° → 前进 3.2m → 转 30° …
                     （距离/角度由指令积分，航向逐次偏转 → 覆盖更多新区域）
反应式避障（步进式）: 订阅 /livox/lidar，前向锥 ±60°、高度带 [-0.15,0.5]m 检测；
                     < stop_dist(0.8m) → 每次只转 avoid_turn_rad(30°) 后重新评估，
                     前方 ≥ clear_dist(1.2m) 或转完一步 ≥ stop_dist 即恢复前进，
                     仍被挡则再转一小步（不再原地大角度打转）
失效安全:            /livox/lidar 超过 lidar_timeout(1s) 无数据 → 停车防盲跑
平滑:                /cmd_vel 20Hz + 线性加减速斜坡 (accel=0.25, ang_accel=0.25)
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `forward_speed` | 0.4 m/s | 前进速度（原 0.3） |
| `turn_rad` | π/6（30°） | 脚本自动转向角（原 180°） |
| `avoid_turn_rad` | π/6（30°） | 避障步进转角（新增） |
| `stop_dist` / `clear_dist` | 0.8 / 1.2 m | 触发 / 恢复距离（带迟滞） |
| `wedge_deg` | 60° | 前向锥水平角 |
| `leg_m` | 3.2 m（=0.4×8） | 每条前进腿长度 |

### 3.2 health_watch：运行期健康看门狗（新增）

| 事件 | 判据 | 行为 |
|---|---|---|
| `FLIP` | \|roll\| 或 \|pitch\| > 0.9 rad | 记录 `health.log`；`--health-abort` 时写 ABORT 哨兵提前中止 |
| `STUCK` | 有前进指令但 15s 位移 < 0.1m | 记录 `health.log`（仅提示） |
| `RTF_LOW` | sim 时间/墙钟 < 0.9（每 10s 窗口） | 记录 `health.log`（卡顿量化） |
| `HEARTBEAT` | 每 10s | 记录 `rtf`、`cmd_v` 供事后复盘 |

### 3.3 run_experiment：仿真时间计时 + 运动驱动三选一

- **采集窗口改为仿真时间**：以 `/clock` 推进 `--duration` 秒为完成判据（墙钟 `×4` 兜底）。即使 RTF<1，落盘轨迹的真实跨度也达到请求时长；
- 运动驱动三选一：

| 模式 | 参数 | 说明 |
|---|---|---|
| 脚本漫游 + 避障 | （默认） | 启动 `drive_node` |
| 手动遥控（WASD） | `--teleop` | 启动 `gui_teleop_node`，窗口内驾驶；关窗口即提前停止采集 |
| 静止 | `--no-drive` | 不起任何驱动 |

- 其他：`--headless`（只起 gzserver）、`--no-rviz`（关 get_urdf 与 fast_lio 两个 rviz2）、`--health-abort`。

### 3.4 性能/渲染优化（针对"一卡一卡"）

| 项 | 原 | 改后 | 收益 |
|---|---|---|---|
| 物理步长 | 0.001s / 1000Hz | 0.002s / 500Hz | 物理开销减半 |
| 世界阴影 | on | off | gzclient 软渲染帧率提升 |
| ray 垂直采样 | 50 | 24（水平 360 不变） | ray cast 开销约减半，点数与真实 MID-360 同量级 |
| 34 个家具模型 | 动态 | `static=true` | 消除无效刚体动力学 |
| 轮加速 | 1.0 | 2.0 rad/s² | 起步/转向响应更快 |


- `--no-rviz`：关掉 get_urdf 与 fast_lio 各自启动的 rviz2（软渲染很吃 CPU）
- `--health-abort`：翻车即中止（安全兜底）


| 键 | 功能 | 键 | 功能 |

## 6. 参数调优参考

`drive_node` 所有参数均可通过 `--ros-args -p` 覆盖（由 `run_experiment` 启动时传入，如需自定义可修改 `run_experiment.py` 的驱动启动命令或在终端单独运行）：

```bash
# 单独运行 drive_node 调试（需已有仿真栈）
# 常用调参：forward_speed 前进速度; turn_rad 自动转向角(0.785=45°);
#           avoid_turn_rad 避障步进角; stop_dist/clear_dist 触发/恢复距离
python3 src/lio_evaluation/scripts/drive_node.py \
    --ros-args -p use_sim_time:=true \
    -p forward_speed:=0.45 \
    -p turn_rad:=0.785 \
    -p avoid_turn_rad:=0.785 \
    -p stop_dist:=1.0 \
    -p clear_dist:=1.4 \
    -p wedge_deg:=70
```

常用调参思路：
- 想更快覆盖：`forward_speed` 0.4→0.45，或 `leg_m` 增大；
- 避障步数太多（医院窄走廊）：`avoid_turn_rad` 30°→45°；
- 想更安全：`stop_dist` 0.8→1.0。

## 7. 已知限制与注意事项

1. **RTF 无法到 1.0**（本机约 0.6~0.9）：瓶颈是 gzserver 单线程 ray cast + 虚拟机软件渲染；运动已平滑（无回弹/无抖动），但 GUI 观感仍受渲染帧率限制。建议自动化实验用 `--headless --no-rviz`，或给 VM 分配更多 CPU/GPU。
2. **手动模式无自动避障**：撞墙/翻车由操作者负责，`--health-abort` 可在翻车时兜底中止。
3. **激光分辨率已下调**（垂直 50→24）：点云变稀但仍在真实 MID-360 点数量级，ATE 保持 2.6cm 验证无损；不建议再降。
4. **Teleop 需要显示器**：纯 SSH/无 X 环境无法用 `--teleop`。
5. **实验目录编号**：`next_experiment_dir` 按数字递增；历史 `experiment_<名称>` 目录不受影响。不想要的验证目录可删除（如 exp_001/002/012/013）。
6. **并发运行冲突**：`run_experiment` 启动时会 `pkill gzserver`，**不要**与其它仿真/实验同时跑。

> **"跑满 90s + 少撞墙 + 多覆盖 + 可手动"**：
