# P5 当前帧鲁棒测量拒绝 (Current-frame Measurement Rejection) — 技术报告

> 日期: 2026-08-30 · 阶段: P5 (项目收尾) · 状态: 完成
> 前置: P0–P4 冻结 (tags p2-final/p3-final/p4-final)。P5 是 FAST-LIO 改进项目的最后阶段。

## 0. 摘要

P5 实现并验证了 **current-frame 匹配质量门控 + 坏测量拒绝 + 短时恢复状态机**。
在 esekfom 第一次 h_dyn_share() 后 (KD-tree correspondence 完成, first-iteration
统计就绪), 由 callback 判定本帧 LiDAR measurement 是否可信; 不可信则显式恢复
propagated state/P (只有 IMU propagation), 并跳过该帧地图插入 (防污染)。

**核心结论 (诚实呈现)**:

| 场景 | degen baseline | P5 robust_gate | 结论 |
|---|---|---|---|
| normal_indoor (clean) | 0.024m | 0.024m, **0 拒帧** | ✅ 零侵入 |
| single_plane (geometry 退化) | 与 RG 数值等价 | 与 degen 完全一致, **0 拒帧** | ✅ geometry 不误杀 |
| V5 holdout (30s 持续 fault) | 0.086m | 2.2~10.5m | ⚠️ 劣于 degen |
| stress (40s 更强 fault) | 1.84m | 10.71m (**5.8× 变差**) | ⚠️ 劣于 degen |

P5 与 P3/P4 的结论**高度一致**: FAST-LIO 对 correspondence fault 的"介入式防护"
(整体降权 / 方向抑制 / 帧级拒绝) 在持续 fault 场景都**难以超越原始滤波器的容错**。
但 P5 额外验证了两件有独立价值的事: (1) current-frame (first-iteration) 匹配信号
**在几何/匹配两条路径上可分离** (single_plane 0 误杀); (2) gate 关闭时**零侵入**
(single_plane 上 robust_gate 与 degen 轨迹数值等价)。

## 1. 背景与动机 (承接 P4 结论)

- P4 发现: correspondence failure 更像"错误测量进入滤波器"的问题; P4 的 matching
  gate 在 fault 段 71% 帧正确阻断, ATE 有 15~50% 改善倾向。
- P5 目标: 不做"降权/抑制", 而是**检测到坏测量直接拒绝** (current-frame, 无
  one-frame delay)。
- 与 P3/P4 的互斥: `--robust-gate` / `--adaptive` / `--directional` 正式实验三选一。

## 2. 设计

### 2.1 esekfom 侧: first-iteration reject hook (评审 R1-R3)

`update_iterated_dyn_share_modified(double R, double &solve_time,
const Vector3d *dir_proj_w, double dir_proj_beta,
bool (*first_iter_gate_cb)(void*), void *gate_ctx, bool *measurement_rejected)`

- callback 在**第一次迭代 (i==-1) 的 h_dyn_share() 之后、K 计算之前**调用。
- 此时 degen_data 已填充 first-iteration 统计 (IMU propagated pose 下完成 matching)。
- 拒绝语义: `x_ = x_propagated; P_ = P_propagated; *measurement_rejected = true; return;`
  → 状态与协方差等于"从未见过本帧 LiDAR", 且不执行任何 measurement 收尾。
  (评审 R2/R3: 显式 restore 使语义在任何迭代点自洽, 不依赖"恰好在第一次迭代 break"
  的脆弱位置约束。)
- `nullptr` (默认) = 关闭, 与 p4-final 数值等价 (零侵入)。

### 2.2 laserMapping 侧: gate + recovery state machine (评审 R6-R12/R26)

判定通道 (P5.0 冻结, 详见 §3):
```
reject_by_num  = rel_num < 0.40      # 有效特征数相对滚动基线骤降
reject_by_ratio= rel_ratio < 0.30    # 有效占比相对滚动基线骤降
res_abnormal   = rel_p90 > 2.0 或 mean_residual > 0.02
reject         = (reject_by_num or reject_by_ratio) AND res_abnormal
```
- **AND 语义** (评审 #13): "特征少但残差正常"不是 matching failure (dropout 保留的
  20% 点匹配仍有效, 拒绝会不必要地丢帧导致漂移)。只有"点少且残差差"才拒绝。
- **不用 absolute 阈值** (P5.0 证明 P2 final-iteration 阈值在 first-iteration 不可用)。

Recovery state machine (评审 #8-#12):
```
NORMAL → REJECT_ONCE → DEGRADED(连续≥2) → RECOVERY_REQUIRED(连续≥5)
恢复: 每帧重新尝试 matching (不降门槛), 满足 recover 阈值 (更宽松) 且连续 2 帧 → NORMAL
```
- 无"放宽 1.5 倍强制放行" (评审 #8); 拒绝≠停止匹配 (评审 #9)。
- RECOVERY_REQUIRED 后允许传播位姿插图 (评审 #10 边界 + 防地图冻结; 详见 §4.3)。

地图门控 (评审 R6/R7/R26):
```
map_update_skipped = measurement_rejected AND !gate_recovery_allow_map_
```
- 拒绝帧默认不插图 (防污染); RECOVERY_REQUIRED 时允许插图 (防地图冻结导致永久失配)。

### 2.3 消息 / 记录 / 编排

- `LioHealth.msg` +5 字段: `measurement_rejected / matching_severity_current /
  consecutive_reject_count (uint16, 内部 int saturating) / recovery_state /
  map_update_skipped`。
- `DegeneracyIteration.msg` +3 字段 (P5.0): `candidate_feature_num /
  effective_feature_ratio / residual_p90`。
- recorder_node.py / run_experiment.py (`--robust-gate`) / mapping.launch.py 参数。

## 3. P5.0 离线预演: first-iteration 信号验证

**动机 (评审 #4/#5/#25)**: P2 阈值在 IEKF 收敛后的 final-iteration 标定, P5 gate
判断的是第一次迭代 (IMU propagated pose), 分布可能不同 → 必须用真实数据重新验证。

**数据采集**: `replay --debug-iterations` → degen_iterations.csv 增加 3 列,
`iteration==1` 行 = first-iteration 统计。5 个 canonical bag replay:
corridor clean / V5 / stress / single_plane / normal_indoor。

### 3.1 关键发现 1: first-iter ≠ final-iter (方向与直觉相反)

| 场景 | eff_num p50 (first/final) | mean_res p50 (first/final) |
|---|---|---|
| corridor_clean | 491 / 492 | 0.0039 / 0.0036 |
| V5_holdout | 316 / 100 | 0.0064 / 0.0246 |
| stress | 207 / 213 | 0.0063 / 0.0112 |

- clean 场景 first≈final; **fault 场景 first-iter 远好于 final-iter** (IMU 传播位姿
  尚未被坏 correspondence 污染)。**P2 的 absolute 阈值 (feats_low/residual) 在
  first-iteration 上不可复用, 甚至会反向误判** (V5 直套 clean 误拒 52.7%)。
- normal_indoor 干净场景 first-iter p90_res p50=0.058, 远超 P2 的 0.04~0.08 量级
  → absolute residual 阈值跨场景不泛化。

### 3.2 关键发现 2: rel-drop (rolling-baseline relative) 通道完全可分

采用 P2 的 relative drop 通道 (`rel_num<0.40 OR rel_ratio<0.30`, baseline=前 30s
非 drop 帧 median):

| 场景 | rel-drop 触发率 |
|---|---|
| corridor_clean | 0/895 (0.0%) |
| normal_indoor | 0/594 (0.0%) |
| single_plane | 0/731 (0.0%) |
| V5_holdout | 347/890 (39.0%) |
| stress | 534/897 (59.5%) |

3 个 clean 场景全部 0 触发, fault 场景 39~60% → **相对信号跨场景泛化**。

### 3.3 关键发现 3: single_plane (geometry) 不触发 matching gate (评审 #13)

single_plane 的 first-iter: eff_num p50=1068 (不低), ratio p50=0.974 (高),
mean_res 0.0061 (正常), **rel-drop 触发 0 帧** → geometry 退化与 correspondence
failure 在 current-frame 层面真正分离。

## 4. 验证

### 4.1 synthetic test (P5.2) — 全 PASS

复刻 gate 逻辑 (Python) 验证:
- E1/E5: clean 不拒; 纯 dropout (残差正常) 不拒 (评审 #13); 点少+残差差触发;
  REJECT_ONCE→DEGRADED→RECOVERY_REQUIRED; map 门控一致性
- E2: geometry (eff 高/残差正常) 不误杀; 纯数量骤降不误杀
- E3: 无放宽恢复路径; 恢复需真正满足 recover 阈值 + 连续确认
- E4: hysteresis 上沿/下沿判定
- E6: consecutive_reject 饱和到 65535 (不回零)

### 4.2 真实 replay 验证 (P5.1→P5.3 迭代发现)

在真实 replay 中发现并修复 3 个实现 bug (每轮都通过 gate 行为数据定位):
1. **map_update_skipped 时序**: publish_lio_health 在 map 门控标记设置前执行 →
   标记移到 update 后立即设置。修复后 `map_update_skipped == measurement_rejected`。
2. **p90 通道假阳性**: clean corridor p90 相对波动天然存在 (转弯/新区域单帧翻倍),
   单独 rel_p90>2 会误报 2.7% → p90 通道改为与数量/占比骤降 AND。
3. **"拒绝→漂移→拒绝"负反馈 (最关键)**: 初始版本 gate 用 rel_num 单独拒绝 →
   V5 上 dropout 帧 (点少但残差正常) 被拒 → 位姿漂移 → 匹配差 → 继续拒 → ATE 165m。
   → 改为 AND 语义 (点少 AND 残差差才拒), ATE 从 165m → 2.16m。
   → RECOVERY_REQUIRED 后允许插图 (防地图冻结), 拒绝帧 map 门控与 rejected 分离。

### 5.3 无害性 (normal_indoor_run1) / regression (single_plane_run2)

| 场景 | degen | robust_gate | 拒帧率 |
|---|---|---|---|
| normal_indoor | 0.024m | 0.024m | **0.00%** |
| single_plane | (数值等价) | 与 degen 完全一致 | **0.00%** |

**single_plane 上 robust_gate 与 degen ATE 完全一致 (1.907368 至 6 位小数)** →
P5 在 geometry 退化下零侵入, 且证明 gate 关闭路径数值无损。

### 5.4 robust_gate 在 fault 场景劣于 degen 的机制分析

V5 上 robust_gate ATE 2.2~10.5m (取决于 baseline 处理), 远高于 degen 0.086m。
机制:

1. **degen 已足够鲁棒**: V5 的 fault (outlier 8% / dropout 80% / noise 0.15) 强度
   不足以让原始 FAST-LIO 发散 (ATE 0.086m)。P5 的拒绝没有保护价值。
2. **拒绝→漂移→拒绝负反馈**: 即使 AND 语义下 dropout 帧被接受, noise 段 (点少但
   mean_residual 正常, 因坏点被平面拟合剔除) 仍难以区分 —— noise 帧被接受 →
   带噪 correction → 位姿漂移 → 后续真匹配失败 → 拒绝 → 地图不更新 → 更漂。
3. **这是机制性问题, 不是参数可调的** (试过 rel 阈值/AND 组合/baseline 过滤,
   均无法在 fault 场景超越 degen)。与 P3/P4 结论一致: 介入式防护难以超越原始
   滤波器的容错。

## 6. 结论与项目收尾

### 6.1 P5 的价值

1. **current-frame (first-iteration) 信号验证**: rel-drop 通道在几何/匹配两条路径
   上完全可分 (clean/geometry 0 误报, fault 39~60% 检出)。这为未来基于当前帧的
   鲁棒 LIO 提供了可用的信号基础。
2. **干净/几何场景零侵入**: normal_indoor 与 single_plane 上 0 拒帧, ATE 与 degen
   数值等价 → P5 不破坏正常与几何退化场景。
3. **机制验证完整**: esekfom reject 语义 (显式 restore) / map 门控 / recovery 状态机
   / hysteresis 全部实现并通过 synthetic 验证。

### 6.2 P5 的局限 (诚实呈现)

持续 correspondence fault 场景 (V5/stress) 下, P5 帧级拒绝因"拒绝→漂移→拒绝"
负反馈**劣于原始 FAST-LIO**。这与 P3 (降权 4.5~8.7× 变差) / P4 (方向抑制 3.7×
变差) 的结论一致, 构成完整的科学结论:

> **对 FAST-LIO 的 correspondence fault, 介入式防护 (降权/抑制/拒绝) 都无法超越
> 原始滤波器的容错; 唯一被验证有效的组件是 P4 的 matching gate (检测阻断), 以及
> P2 的误差归因 (区分 geometry vs correspondence)。**

### 6.3 项目总叙事 (P1→P5)

- **P1**: 能检测几何退化 (Hessian-based)。
- **P2**: 能区分 geometry / correspondence / IMU 低激励 (Error Attribution), 冻结阈值。
- **P3** (证伪): 整体 LiDAR 降权在严重退化/故障有害 (正反馈: 降权→漂移→误判→继续降权)。
- **P4** (部分证伪): 方向性抑制无法解决真正的信息缺失; matching gate 在 fault 段
  阻断有效 (P5 前的唯一正向结果)。
- **P5** (机制验证 + 边界确认): current-frame gate 机制完整可用且 clean 零侵入,
  但在持续 fault 上确认了介入式防护的系统性边界。

## 7. 遗留 (不阻塞)

- robust_gate 默认关闭 (`--robust-gate` 显式开启), 与 p3/p4-final 互斥, 保证
  baseline 行为不变。
- single_plane ATE 存在回放噪声 (1.91 vs P4 报告 1.58), 与 P5 无关 (degen 也如此)。
- 未来方向 (超出本项目): 帧级拒绝需与"短时重定位/地图回环"配合才能处理持续 fault;
  纯 current-frame 拒绝不足以单独解决。
